## 2. 从第一性原理推导验收条件

上架的对象不是一个版本号，而是用户将实际安装的一组字节、这些字节的行为，以及商店对这些行为的说明。准备工作必须建立下列对应关系。

| 原始事实 | 推导出的要求 | 需要的证据 |
| --- | --- | --- |
| 用户安装的是包，不是源码目录 | 源码已有语言或功能不代表 ZIP 已包含；必须直接检查最终包 | ZIP 文件清单、逐文件比较、manifest 和 SHA-256 |
| 浏览器焦点、网络和后台生命周期是异步的 | 旧观察可能晚到；正常同步成功不能证明切换时正确 | 乱序、取消、超时、停止通知、后台重启测试 |
| 私密页面信息不能离开浏览器的私密上下文 | 不能发送私密 URL、标题或图标；结束旧普通页只能用无页面信息通知 | 冷启动私密与普通转私密两类网络证据 |
| 网页计时依附 Patina 的有效桌面活动 | 扩展收到 HTTP 成功不证明桌面记录正确 | 对已公开 Patina 的实际记录、截止、匿名路径联调 |
| Firefox 正式用户包依赖 Mozilla 签名 | 未签名测试与 listed 发布分开；不能用试签名占用候选版本 | 版本历史检查、未签名测试记录、签名后待办 |
| 商店描述会影响用户授权和审核判断 | manifest、payload、隐私政策、listing 和审核说明必须描述同一行为 | 文案对照、权限表、实际测试结果 |
| 发布失败可以重试，已发布内容不能偷换 | 候选需固定源码和哈希，恢复流程不得覆盖冲突附件 | 候选记录、确定性构建、发布工作流检查 |

因此，验收依赖五条证据链：版本可用、包等于源码、行为符合协议、文案符合行为、后续发布不改包。任何一条断开都不能靠总体评分抵消。
